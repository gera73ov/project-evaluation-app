# Протокол проверки восстановления № 1 (QA-025)

Заполнен по шаблону `manuals/operations.md`, раздел 10, по автоматическому прогону
`e2e-stand.sh ops-suite` (`deploy/backup/verify-restore.sh`) на домашнем стенде test.
Это не квартальная проверка на stage: железо слабее, ключ — рабочий ключ стенда, а не копия из
сейфа ИБ. Квартальная проверка на stage остаётся по регламенту (`manuals/regulations.md`).

```
Протокол проверки восстановления № 1   Дата: 12.11.2026   Стенд: test (домашний стенд, Linux Mint 22.3)
Версия приложения: main 44b0d4b (прогон e2e-stand 43186363305)
Копия от: 12.11.2026 09:03:52 UTC (полная, pgBackRest, aes-256-cbc) + WAL до: 09:05:16 UTC (остановка)
Ключ: рабочий ключ стенда (.env стенда); копия из сейфа ИБ не использовалась

Сбой: 09:05:16 UTC — остановлены приложение и БД, том pgdata удалён и создан пустым
Начало восстановления: 09:05:16 UTC   Окончание (healthcheck зелёный): 09:05:56 UTC   RTO: 40 с (≤ 4 ч)
Последняя правка до аварии: проба after_full, записана после полной копии (≈ 09:04:00 UTC)
Последняя правка после восстановления: проба after_full на месте   RPO: ≤ 76 с (≤ 15 мин)
estimator audit verify: в автоматическом прогоне не выполнялась
«Состояние системы»: не проверялось (после восстановления прошли e2e и обновление с откатом)

Вывод: уложились.   Подписи: эксплуатация ________   ИБ ________
```

Что проверено дополнительно в том же прогоне: обновление `dev → e2e-next` с резервной копией перед
ним и откат обратно (`deploy/scripts/upgrade.sh`, `rollback.sh`) — успешно.

Для квартальной проверки на stage к этому протоколу добавить: ключ из сейфа ИБ по акту вскрытия,
`estimator audit verify` и снимок «Состояния системы» после восстановления.
