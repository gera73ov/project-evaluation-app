# DEC-20261109-core-history-moderator

- **Тип:** решение (DEC), уровень A1
- **Время:** 2026-11-09T19:20:00Z
- **Трек:** CORE (CORE-021, CORE-022, закрытие CORE-018); потребители — FE (история листа, счётчик
  «Изменения модератора»), NTF (письма-дайджесты), CORE-043 (событие в ленте)
- **Основание:** SPEC FR-TREE-25, FR-TREE-34, 1.1, 11.5 №3, BR-BR-02; contracts/openapi.yaml
  (`getNodeHistory`), notifications.yaml (`moderator_change`)

## Решение

1. **История** `GET /nodes/{id}/history`: записи `node_history` новыми сверху (по версии узла),
   курсор подписан (`node-history`), страница по `limit` (по умолчанию 50). Автор — `UserRef` или
   `null` («Система»). Видна всем с `tree.read`.
2. **«Вернуть это значение»** отдельной операции не имеет: клиент шлёт выбранное значение обычным
   `PATCH /nodes/{id}` с текущей `base_version`. Так возврат проходит весь путь правки: новая запись
   истории, снятие «Проверено», сброс «готово», захваты и конфликты.
3. **«Изменение модератора»** — правка участником с ролью модератора проекта, который не эксперт
   дисциплины ветки. Экспертам этой дисциплины (кроме автора) — `moderator_change` с узлом и полями:
   правка — изменённые ключи (`title`, `type`, `o`, `r`, `p`, `multiplier`, `comment`), добавление,
   удаление, восстановление, разбиение, сворачивание, дублирование — `structure`, перенос — `move`
   (при переносе между ветками — экспертам обеих дисциплин). Правка эксперта и правка без изменений
   уведомлений не дают.
4. **«Проверено» и «готово» при правке модератора** снимаются по таблице BR-BR-02, как у эксперта:
   переименование и комментарий их не трогают. FR-TREE-34 говорит о правке цифр; таблица BR-BR-02
   точнее и одна для всех ролей.
5. **CORE-018 закрыт**: строки TC-BR-01 для удаления, восстановления, разбиения, сворачивания и
   переноса проверены тестами CORE-016/017 и `test_history_api.py`.
