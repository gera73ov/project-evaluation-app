# DEC-20261110-core-exports-engine

- **Тип:** решение (DEC), уровень A1
- **Время:** 2026-11-10T15:00:00Z
- **Трек:** CORE в роли EXP (EXP-003…010). Потребители: FE-093
  (кнопки выгрузок), EXP-007…010 (свои построители на том же движке), QA (TC-SEC-04,
  TC-MONEY-01, G-18).
- **Основание:** SPEC FR-EXP-01…06, BR-MONEY-04…06, R-01, FR-SNAP-01, SEC-WEB-07, NFR-REL-06;
  contracts/exports.yaml (`hours_xlsx`, `money_xlsx`, `common`), openapi `createExport`,
  `getExport`, `downloadExport`, audit-events `export.created`/`export.downloaded`.

## Решение

1. **Движок** (`exports/engine`):
   - `start` пишет `export_files` (`pending`, срок 24 ч) и после commit ставит задачу Celery
     `estimator.exports.build`.
   - `run` строит файл построителем вида (`@engine.register(kind)`) и кладёт его в
     `EXPORTS_DIR/<id>.<ext>` (том `exports`, новая настройка, по умолчанию `/data/exports`).
     Затем статус становится `ready` и пишется аудит `export.created` (kind, snapshot_id,
     with_money, rows).
   - Сбой построителя → `failed`, `GET /exports/{id}` отвечает 409 `EXPORT_FAILED`. В контракте
     у `ExportJob.status` только `pending`/`ready`.
   - Чужая выгрузка → 404 (даже модератору проекта). После срока → 410 `EXPORT_EXPIRED`.
     Скачивание пишет аудит `export.downloaded`.
   - Ежечасная задача (`:15`) удаляет просроченные строки и файлы. Срок — константа 24 ч, как
     `retention_hours` в exports.yaml. Настройку `retention.export_files_hours` пока никто не
     читает: это общий вопрос «Хранения» (ADM).
2. **Скачивание:** `application/octet-stream` (так в контракте), `Content-Disposition:
   attachment` с `filename*` UTF-8, `nosniff`, `no-store`.
3. **Права:**
   - gate (любое из `export.hours`/`export.money`) и явная проверка права вида:
     `money_xlsx` → `export.money` (с TOTP), `hours_xlsx` → `export.hours`;
   - лимит 30 в час на пользователя (`LIMITS["exports"]`);
   - `with_money` фиксируется при постановке;
   - снимок не из проекта → 422.
4. **Источник** (`exports/source`): обе книги строятся из `payload` снимка. Для текущего
   состояния он собирается `snapshots.capture`, для снимка берётся сохранённый. Деньги берутся
   через `services.money.snapshot` (G-11 соблюдён). Так EXP-006 даётся бесплатно: файл из
   снимка не меняется после правок.
   - В снимке нет «Проверено»: из снимка колонка пустая.
   - Категории меток берутся из справочника по id.
5. **«Оценка»:**
   - строки 1–3 — отметка, заголовки колонок — строка 5, данные — с 6;
   - уровень и группировка строк Excel (outline), отступ названия — выравниванием;
   - ветка «не нужно» — одна строка, выключенная фаза — строка «фаза выключена»;
   - сквозная фаза УП деревом не выводится, УП — строкой «Управление проектом N %»;
   - «Цифра для КП» выделена заливкой в строке E/P80/P90.
   - Деньги: стоимость листа — `округл(E · ставка дисциплины)`, у узлов и фаз — сумма
     округлённых строк, валюта — `округл(₽ / курс)` построчно. У P80/P90 денег на «Оценке» нет:
     они на «Для КП».
6. **«Для КП»:**
   - из `calc.calculate_money`: строки дисциплин и УП по E и по цифре КП в ₽ и в валюте, НДС,
     итоги, «Цифра для КП» в часах, срок, блок E/P80/P90;
   - если ставки не заданы, вместо сумм — строка «не заданы ставки: …».
7. **Вопросы заказчику (EXP-007):**
   - `POST /projects/{id}/customer-questions/export` (`cq.manage`); все `thread_ids` должны
     быть вопросами заказчику этого проекта, иначе 422;
   - в файл идут выбранные, кроме снятых, по номеру; «Раздел» — путь узла или «Проект»;
     текст — первое сообщение вопроса (отозванное — пусто);
   - «новые» → «отправлен» (`flow.mark_sent`) делает построитель в той же транзакции, что и
     файл: не удалась выгрузка — статусы прежние;
   - Excel: отметка в строках 1–3, шапка с 5-й строки, таблица ниже; Word: отметка первым
     абзацем и в колонтитулах, таблица «№, Раздел, Вопрос, Ответ».
8. **Сравнение (EXP-008):** `POST /snapshots/{id}/diff/export {with}` (`export.hours`),
   `with` — `current` или снимок того же проекта, иначе 422. Содержимое — тот же
   `diff.compare`; деньги («в КП», вклад курса, «Δ, ₽») — только при `money.read` у
   выгружающего. «Было/Стало» узла — строкой «O–R–P ×N → E». Пересчёт УП — строкой «параметр
   проекта». Колонки «Δ, <валюта>» нет: построчной разницы в валюте сравнение не считает.
9. **Вкладки статистики (EXP-009):** `GET /projects/{id}/stats/{tab}/export?format=xlsx`
   (`export.hours`). Одна вкладка — один файл, данные — те же сервисы, что у экранов.
   Деньги (стоимость, «в КП», лист «Сумма для КП» у «Итогов») — только при `money.read`.
   Отступления от колонок exports.yaml там, где сервис статистики таких данных не считает:
   - «Объёмы по типам» — только тип и число единиц (E по типу экран тоже не показывает);
   - «Доли и соотношения» — соотношение, норма, факт, оценка;
   - «Кандидаты» — путь, E на единицу, E, σ/E, пометка.
   Имя файла: `<проект>_<дата>_статистика-<вкладка>.xlsx`.
10. **«Допущения и риски» в Word (EXP-009):** `GET /projects/{id}/assumptions/export`
    (`export.money`). Разделы по категориям меток и «Обоснование процента управления
    проектом»; путь узла — 8 pt; денег нет.
11. **Портфель (EXP-010):** `POST /portfolio/export {from, to}` (`portfolio.export`, TOTP).
    Листы «Реестр», «Сводка», «Параметры» из `services.portfolio`; `from > to` → 422. Других
    фильтров контракт не передаёт: в «Параметрах» — «все».
12. **Шаг подтверждения (step-up):** `GET /exports/{id}` и `…/download` — без step-up (так в
    контракте), хотя среди прав есть `audit.export`. Step-up нужен при постановке выгрузки
    аудита, а файл отдаётся только её автору. Сам CSV аудита (`audit_csv`) — за треком SEC/ADM.
13. **Проверка контракта ответов** (`tests/contract/openapi_impl.check_response`): тело со
   схемой `format: binary` проверяется как файл, а не как JSON.
