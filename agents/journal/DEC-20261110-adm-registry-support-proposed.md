# DEC-20261110-adm-registry-support-proposed

- **Тип:** решение (DEC), уровень A1
- **Время:** 2026-11-10T12:00:00Z
- **Трек:** ADM (ADM-005, ADM-009, ADM-010, ADM-011); потребители — FE-072, FE-073, FE-091, QA-003
- **Основание:** SPEC 7.5, 3.2–3.4, BR-PRJ-07, BR-ADM-03, FR-ADM-06, FR-TREE-03, TC-ADM-02,
  SEC-AUTHZ-05, CL-09; contracts/openapi.yaml, permissions.yaml, audit-events.yaml

## Решение

1. **Реестры** (`/admin/projects`, `/system/projects`) — по убыванию даты создания, затем `id`;
   курсор подписан. Денег, итогов и дерева в строке нет. `days_without_moderator` — полные сутки
   с `no_moderator_since`. Модераторы выводятся с `is_active`, чтобы экран показал заблокированных.
2. **Передача модератора** идёт через тот же сервис команды (`put_members`), что и экран
   «Команда», но с `via: "transfer"` в `project.team.changed`. Новый модератор должен иметь
   системную роль «Модератор» (422 `MEMBER_ROLE_REQUIRED`); снять последнего — 409
   `LAST_MODERATOR`. Назначение себя — `added_by_admin_self` в ответе и аудите (BR-ADM-03).
3. **Режим поддержки.** Сессия принадлежит паре «администратор — проект», живёт 60 минут.
   Повторное открытие закрывает прежнюю сессию этого администратора и открывает новую (новая
   причина — новая запись аудита и уведомление). Права — только `read_only` без денег и заметок
   (R-SUPPORT в каталоге прав). Уведомление модераторам уходит в любом статусе проекта.
4. **Предложенные типы.**
   - «Добавить в словарь»: если в словаре уже есть тип с тем же названием (без регистра) — 409
     `INVALID_TRANSITION`, предлагаем «Объединить».
   - «Объединить»: цель — только активный тип словаря, иначе 422. Узлы проекта (включая
     удалённые) перепривязываются, у живых — `node.updated` в реальном времени; локальный тип
     получает `merged` и `merged_into_id` и пропадает из типов проекта.
   - «Отклонить»: тип остаётся локальным в проекте, но уходит из списка предложенных.
   - Повторное решение — 409 `INVALID_TRANSITION`; аудит `dict.proposed_type.decided`.
