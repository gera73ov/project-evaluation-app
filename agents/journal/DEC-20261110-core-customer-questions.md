# DEC-20261110-core-customer-questions

- **Тип:** решение (DEC), уровень A1
- **Время:** 2026-11-10T12:00:00Z
- **Трек:** CORE (CORE-044, CORE-045), контракт CR-013. Потребители: EXP-007 (выгрузка →
  `mark_sent`), FE-016 (шапка «Открыто»), список «Вопросы заказчику» (11.11), ADM-012, QA-015
  (G-17, G-22, TC-CQ-01).
- **Основание:** SPEC 4.4, BR-CQ-01/02, FR-CQ-01…03, Q-46, C-05, FR-TREE-11, 11.4 №3;
  contracts/openapi.yaml (`listCustomerQuestions`, `answer/withdraw/editCustomerQuestion`,
  `resolveThread`, `reopenThread`), ws-events `customer_question.updated`.

## Решение

1. **Номер В-NNN** выдаёт создание вопроса (CORE-040): `UPDATE projects SET next_question_no =
   next_question_no + 1 … RETURNING` в той же транзакции. Снятые вопросы номер сохраняют, номера
   не переиспользуются.
2. **Переходы** (диаграмма 4.4):
   - `new → sent` — `flow.mark_sent` (EXP-007 после выгрузки); прочие статусы пропускаются.
   - `new`/`sent → answered` — «Внести ответ заказчика».
   - `answered → closed` — через `resolveThread`; `closed → answered` — через `reopenThread`.
   - `new`/`sent → withdrawn` — с причиной.
   - Остальное → 409 `INVALID_TRANSITION`, в том числе второй ответ в «отвечен».
3. **Кто:** решает gate по `cq.*` и условию `cq_status_new`, резолвер `/threads/{id}` отдаёт
   автора и статус.
   - Автор-эксперт правит и снимает только «новый», закрывает свой «отвечен».
   - Модератор и пресейл делают всё, переоткрывают только они.
   - В «Архиве» запрещено (409), в «Завершена» ответы вносятся (M3.4-06).
4. **`threads.status`** у вопроса заказчику — `resolved` в «решён» и «снят», иначе `open`. Так
   счётчики открытых вопросов не считают закрытые и снятые.
5. **Ответ заказчика:**
   - сообщение `customer_answer` (до 10 000), автор — кто внёс; `answered_at`;
   - уведомление `answer_to_my_question` автору вопроса;
   - события `message.created` и `customer_question.updated`.
6. **Правка** (`PATCH /threads/{id}/question`):
   - разрешена в «новом», «отправлен» и «отвечен»;
   - в «новом» — `message_history(edit)`;
   - после «отправлен» — `edited_after_sent = true` и `message_history(edit_after_sent)`;
   - правка тем же текстом ничего не пишет.
   - `PATCH /messages/{id}` автору после «отправлен» → 403 (BR-CQ-01).
7. **Список:** порядок по номеру, курсор по номеру. Фильтры — статус и дисциплина узла. `path` —
   названия от фазы до узла, у вопроса проекта пусто. `answer` — последний ответ заказчика.
8. **Счётчики (CORE-045, CR-013):** в `Tree.totals` добавлены `open_questions`, `questions_to_me`
   и `risks`.
   - «Мне» — по адресатам вопроса (DEC-20261110-core-discussions, п. 3).
   - Риски — живые листья с меткой категории `risk` в комментарии.
   - В события обсуждений счётчики не кладутся: «мне» у каждого зрителя своё. Клиент
     пересчитывает их по адресатам из событий.
   - Список открытых вопросов с путём — `listThreads?status=open` (путь клиент берёт из дерева).
