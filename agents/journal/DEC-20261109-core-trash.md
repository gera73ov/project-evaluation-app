# DEC-20261109-core-trash

- **Тип:** решение (DEC), уровень A1
- **Время:** 2026-11-09T18:50:00Z
- **Трек:** CORE (CORE-017); потребители — FE-018 (корзина), QA-014, трек DOC (документы в корзине)
- **Основание:** SPEC FR-TREE-24, Q-04, BR-TREE-01/03/05/06, BR-BR-02, GAP-06, 17.2 (G-15, G-16);
  contracts/openapi.yaml (`deleteNode`, `getTrash`, `restoreTrash`), errors.yaml
  (`RESTORE_TARGET_UNAVAILABLE`), ws-events (`node.deleted`, `node.restored`); закрывает открытый
  вопрос DEC-20261109-core-structure

## Решение

1. **Удаление** `DELETE /nodes/{id}` — узел со всем живым поддеревом одним пакетом
   (`services/trash/batch.trash`). Строку фазы и ветку дисциплины так не удаляют: 403 (422 в контракте
   операции нет; ветку убирает «Удалить дисциплину»). «Готово» → «черновик», «Проверено» снимается с
   родителя и предков. Признак «нужно подтверждение» клиент выводит из дерева (дети, счётчики
   обсуждений): отдельного поля в контракте нет.
2. **Список** — пакет = элемент: корень (узел, чей родитель не в пакете), число узлов, автор и время
   удаления, `purge_at` = удаление + 30 дней (за 3 дня клиент пишет «будет удалён через N дн.»).
   Модератор видит всё, эксперт — пакеты своих дисциплин (scope `own_discipline`), пресейл — только
   документы (их добавит трек DOC; пока пусто). Пакеты веток дисциплин, удалённых из проекта, в
   корзину не выводятся и не восстанавливаются (404): ветку возвращает «Добавить дисциплину».
3. **Объект `/trash/{batch_id}`** для gate — проект и дисциплина корня пакета; gate теперь читает и
   параметр пути `batch_id`. Статусы проекта («Завершена», «Архив») отсекает gate по матрице 3.4.
4. **Прежнее место.** Удалённые предки корня восстанавливаются вместе с ним — только сами предки, без
   остальных узлов их пакетов. Удалённая ветка дисциплины на пути заменяется живой веткой той же пары
   «фаза × дисциплина». Позиции прежние.
5. **Недоступное место** — 409 `RESTORE_TARGET_UNAVAILABLE` с `reason` (`discipline_removed`,
   `phase_disabled`, `branch_not_needed`) и `discipline_id`. Повтор с `target_parent_id`: живой узел или
   ветка той же дисциплины (иначе 422), не лист с оценкой (422), ветка которого принимает узлы (иначе
   снова 409). Корни встают первыми у нового родителя, у поддерева меняется фаза; в истории
   `restore` — `parent`, `position`, `phase_id`.
6. **Лист с оценкой под возвращаемыми детьми** (пакет «Свернуть в лист» или оценка, поставленная после
   удаления детей): O/R/P/×N листа снимаются отдельной правкой `update` с прежними значениями в
   истории (BR-TREE-01: у узла либо дети, либо оценка). Так свёрнутый узел возвращается в исходный вид.
7. **Лимиты** BR-TREE-05/06 проверяются до записи (с учётом восстанавливаемых предков). Восстановление —
   одно событие `node.restored` со всеми узлами; «готово» → «черновик» (и «не начато» → «черновик»).
8. **Ночная очистка** — задача Celery `estimator.trash.purge` в 02:30: строки узлов с
   `deleted_at` старше 30 дней удаляются окончательно, история и обсуждения — каскадом FK.
9. **Форма `x-permission`**: ApiRouter сохраняет список из одного кода списком (как в контракте
   `getTrash`); раньше такой список превращался в строку и не сходился с API-004.
