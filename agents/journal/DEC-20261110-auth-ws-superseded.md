# DEC-20261110-auth-ws-superseded

- **Тип:** решение (DEC), уровень A1 — технический долг
- **Время:** 2026-11-10T19:55:00Z
- **Трек:** AUTH (AUTH-002) и RT (RT-008); потребитель — FE (PR #100)
- **Основание:** FR-SESS-03 (смена идентификатора после TOTP и step-up), FR-SESS-02, RT-008

## Наблюдение

После step-up или TOTP `SessionService.rotate` меняет идентификатор сессии, а старый отзывает с
причиной `superseded`. Отдельного события `SessionEnded` нет. Однако открытый WebSocket всё ещё
держит старый id. Перепроверка соединения раз в 2 с (`realtime/ws`, `WsSession._current`) его не
находит, отправляет `session.ended` и закрывает соединение кодом 4401. Из-за этого интерфейс
уходил на экран входа.

## Решение

Сейчас это закрыто на клиенте (PR #100): перед выходом клиент проверяет `GET /me`. Серверную
правку отложили по согласованию с координатором.

## Технический долг: серверная правка (одним PR, AUTH и RT вместе)

1. `rotate` оставляет в Redis короткую метку «сессия заменена» (TTL около 60 с, ключ по хэшу
   старого id).
2. `resolve_principal` для такого id отдаёт причину `superseded`.
3. `WsSession._current` по этой причине закрывает соединение кодом 1012 (`CLOSE_RESTART`,
   переподключение) без `session.ended`. Клиент переподключится с новой cookie.
4. Тест: rotate при открытом WebSocket даёт закрытие 1012 и не даёт `session.ended`.
