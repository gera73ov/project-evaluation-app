## Суть

Введён регламент `AGENTS.md` v1.0. При его составлении приняты решения, которые SPEC и `PLAN.md` не фиксировали:

1. Модель ветвления — trunk-based с короткоживущими ветками; Git Flow не используется; релизные ветки — только по решению владельца, не раньше этапа 7.
2. Сливает PR в `main` только владелец; способ слияния — merge commit (как в PR #1–#5).
3. Обновление опубликованной ветки — только слиянием `origin/main`; rebase и force-push опубликованных веток запрещены без санкции.
4. Сообщения коммитов — Conventional Commits, область — код трека, описание по-русски; прошлую историю не переписываем.
5. Шкала приоритетов коллизий: безопасность → целостность данных → корректность → согласованность процесса → скорость; при равенстве — 7 детерминированных правил (раздел 4.2), в том числе фиксированный порядок треков SEC, DB, API, AUTH, CORE, RT, ADM, NTF, EXP, INF, FE, QA, DOC, PM.
6. Журнал решений — один файл на запись в `agents/journal/`, чтобы параллельные агенты не конфликтовали.
7. Уровни автономии A0/A1/A2; всё, что нельзя однозначно отнести к A0 или A1, считается A2.
8. Глубина делегирования — один уровень: субагент не запускает субагентов, не пушит и не обращается к владельцу.
