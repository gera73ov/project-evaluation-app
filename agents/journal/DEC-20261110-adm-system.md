# DEC-20261110-adm-system

- **Тип:** решение (DEC), уровень A1
- **Время:** 2026-11-10T11:30:00Z
- **Трек:** ADM (ADM-001…004); потребители — FE-060…065 (раздел «Система»), FE-091, AUTH-015,
  AUTH-016, AUTH-017, AUTH-018, INF (бэкап), QA
- **Основание:** SPEC 3.2, 7.1, FR-SA-02…07, FR-2FA-03, BR-ROLE-02/03, SEC-AUTH-05/07,
  SEC-AUD-03/04/05, NFR-REL-06, 18.4; contracts/openapi.yaml «Система», settings.schema.json,
  permissions.yaml, audit-events.yaml; CR-009

## Решение

1. **Разделы настроек.** В API раздел `app` соответствует `x-sections.system` контракта (адрес и
   часовой пояс); `method` здесь нет — это `/admin/method-settings` (ADM-007). Неизвестный раздел —
   404. Чтение отдаёт все ключи раздела (сохранённое или значение по умолчанию), секреты —
   `{"set": bool}`.
2. **Запись частичная.** В `values` — только меняемые ключи. Секрет: строка — новое значение
   (шифруется), `null` — удалить, `{"set": true}` — оставить. Ключи `x-owner: system`
   (`app.setup`, `auth.ad.verification`) записать нельзя — 422. Дополнительно к схеме:
   `min_length ≤ max_length`; у SMTP с сервером нужен адрес отправителя; у включённого SIEM — адрес.
3. **Проверка по контракту без новой зависимости.** `jsonschema` — только dev, поэтому
   `admin/settings/schema.py` проверяет подмножество JSON Schema, которое использует контракт;
   неизвестное ключевое слово роняет загрузку. Совпадение с `jsonschema` — unit-тест по всем ключам.
   Образ кладёт `settings.schema.json` в пакет, как каталог прав (`api.Dockerfile`, `.gitignore`).
4. **Аудит и оповещения.** `system.settings.changed`: раздел `security` — событие на каждый
   изменённый ключ (`section` = ключ: так работают условия оповещений по сетям и TOTP), остальные —
   одно событие на раздел. Значение секрета в `changes` — `{"changed": true}` (аудит дополнительно
   маскирует ключи с `password`). Смена SMTP: `before_smtp_change` до записи (SEC-011).
5. **Раздел `auth` до AUTH-015/018.** `auth.mode` меняет только переход (422), любые параметры AD —
   409 `AD_CHECKS_REQUIRED`, пока нет проверок подключения и входа. Тот же ответ — выбор AD в
   мастере.
6. **Тестовое письмо (CR-009)** — синхронно, `system.settings.write` без step-up (ничего не
   пишет). Сохранённый пароль подставляется, только если `host`, `port`, `username` совпадают;
   иначе без пароля в форме — 422.
7. **Учётки «Системы».** Список — учётки с ролями суперадминистратора, администратора, аудитора ИБ.
   `PATCH roles` — полный набор ролей «Администратор» и «Аудитор ИБ» (роль суперадминистратора
   там не меняется: 403); правила — `role_rules` (SEC-017). Выдача и снятие ролей, блокировка,
   разблокировка, создание пишут `system.privileged_account.changed` (оповещение всегда), без
   дублирующего `users.roles.changed` — иначе два письма ИБ на одно действие. После изменения ролей
   и разжалования сессии учётки завершаются. Разблокировка суперадминистратора проверяет предел 3.
   Свою учётку менять здесь нельзя (403). `LAST_SUPERADMIN` через API недостижим (действует
   активный суперадминистратор), проверка оставлена для согласованности с CLI.
8. **Сбросы `/system/users/{id}/…`** — только учёткам с ролями «Системы», кроме себя; остальным —
   404 (их сбрасывает администратор, ADM-006).
9. **«Состояние системы».** Неизвестное состояние (проверка цепочки ещё не выполнялась, нет
   метки бэкапа) — красный. SMTP — сервер настроен и принимает TCP; красный и при недоставленном
   оповещении ИБ. LDAP в режиме «Приложение» — зелёный «не используется». Очередь — брокер доступен
   (порог длины SPEC не задаёт). Бэкап — файл-метка `BACKUP_MARKER_PATH` (ISO-время в первой строке
   или время изменения), не старше 26 часов (18.4); скрипт бэкапа INF должен писать этот файл.
   `audit_purge` — нет записей старше срока хранения плюс месяц. «AD-проверка пропущена» — с AUTH-016.
10. **Мастер.** Шаги в любом порядке и повторяемы; `app` требует адрес; шаг `auth` в режиме
   «Приложение» сохраняет политику паролей; `first_admin` — создать администратора или пропустить,
   если он уже есть. `complete: true` — когда отмечены все пять шагов и есть администратор. После
   завершения — 409 `SETUP_ALREADY_COMPLETED`. Режим AD в мастере — с AUTH-015/017.
