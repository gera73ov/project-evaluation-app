# DEC-20261109-core-local-node-types

- **Тип:** решение (DEC), уровень A1
- **Время:** 2026-11-09T14:10:00Z
- **Трек:** CORE (CORE-020, серверная часть CR-006); потребители — FE-013, FE-020…FE-027, ADM (предложенные типы)
- **Основание:** SPEC FR-TREE-03, GAP-07, NFR-LIM-01, 3.3, 15.2; contracts/openapi.yaml
  (`listProjectNodeTypes`, `createLocalNodeType`, `NodeTypeIcon`)

## Контекст

Контракт CR-006 задаёт состав списка «активные типы словаря и локальные типы проекта», но не говорит,
что делать с выключенными типами словаря, на которые уже ссылаются узлы, и с локальными типами после
решения администратора.

## Решение

1. **Выключенный тип словаря** входит в список проекта с `is_active = false`, пока на него ссылается
   живой узел проекта: клиенту нужно название и иконка в дереве; в меню «+» клиент показывает только
   `is_active = true`.
2. **Локальные типы после решения администратора:** «отклонён» (`rejected`) остаётся в проекте как
   был (FR-TREE-03 не велит его убирать); «объединён» (`merged`) в список не входит — узлы уже
   перепривязаны к типу словаря; «добавлен в словарь» (`accepted`) приходит как тип словаря.
3. **Название** обрезается по краям, 1–50 символов, одной строкой; совпадение с названием другого
   типа не запрещено (SPEC не требует уникальности).
4. **Создание** пишется в журнал проекта (`project.node_type`, `{name, icon}`); версия проекта не
   повышается и события в канал проекта нет — тип ещё не влияет на дерево, другие клиенты получат
   его со следующим списком или вместе с узлом этого типа.
5. **Набор иконок** — `NodeTypeIcon` в `services/tree/local_types.py`, совпадает с контрактом
   (проверяет API-004 через схему запроса).

## Последствия

ADM-трек строит «Предложенные типы» по `proposal_status = proposed`. Если клиенту понадобится
мгновенное появление нового типа у других участников, событие добавляется через CR.
