# DEC-20261110-core-documents

- **Тип:** решение (DEC), уровень A1
- **Время:** 2026-11-10T15:00:00Z
- **Трек:** CORE (EXP-011, EXP-012). Потребители: FE-092 (вкладка «Документы заказчика», корзина,
  «📎»), QA-009 (TC-SEC-10).
- **Основание:** SPEC FR-DOC-01, 11.7 №1–6, SEC-WEB-08, SEC-WEB-10, SEC-CRYPT-06, NFR-LIM-01,
  GAP-06, Q-04, 15.4 `document.scanned`; contracts/openapi.yaml (`listDocuments`,
  `uploadDocument`, `downloadDocument`, `deleteDocument`, `restoreDocument`, `TrashBatch`),
  errors.yaml, audit-events.yaml (`project.document.changed`, `security.file_infected`).

## Решение

1. **Код:** пакет `documents/`:
   - `upload.py` — тип по сигнатуре, имя, лимиты;
   - `storage.py` — файл на томе `documents` по `storage_key`, шифрование и расшифровка;
   - `scan.py` — клиент `clamd` (`zINSTREAM` по TCP), подменяемый сканер;
   - `tasks.py` — задача Celery `estimator.documents.scan` и ночная `estimator.documents.purge`
     (02:45);
   - `service.py` — список, приём, скачивание, корзина, очистка.

   Роутер — `api/v1/documents.py`, резолвер `/documents/{id}` (проект, статус, `kind=document`).
   Новые настройки: `DOCUMENTS_DIR`, `CLAMAV_HOST`, `CLAMAV_PORT`, `CLAMAV_TIMEOUT_SECONDS`.
2. **Тип по содержимому.**
   - PDF — `%PDF-` в начале.
   - DOCX и XLSX — ZIP, у которого в `[Content_Types].xml` ровно одна главная часть Word или Excel.
   - Отказ 415: главная часть `macroEnabled`, `vbaProject.bin` в пакете, шаблоны, всё прочее.
   - Расширение не важно: PDF с именем `.docx` принимается как PDF, `.exe` с именем `.pdf` — 415.
3. **Лимиты.**
   - Файл больше 50 МБ → 413, пустой → 422.
   - Место проекта — живые документы `pending` и `clean`. Корзина и отклонённые антивирусом
     место не занимают.
   - Больше 1 ГБ → 409 `PROJECT_STORAGE_LIMIT` с `used_bytes` и `limit_bytes`.
   - Счёт идёт под блокировкой строки проекта, чтобы параллельные загрузки не обошли лимит.
   - Восстановление из корзины проверяет лимит заново, как требует контракт.
4. **Шифрование сразу при приёме (строже PLAN).** PLAN шифрует после проверки, здесь файл
   шифруется ещё до неё.
   - Ключ — свой ключ данных на файл, `key_enc` под мастер-ключом с контекстом
     `contexts.document_key(id)`. Это потоковый AES-GCM из SEC-003, AAD — id документа.
   - На томе `documents` открытого содержимого нет даже в карантине.
   - Проверка расшифровывает поток прямо в сокет `clamd`.
   - Открытый текст лежит только во временном файле multipart на `/tmp`, а это tmpfs. В compose
     для api и worker tmpfs увеличен до 256 МБ: при 64 МБ не прошла бы и одна загрузка 50 МБ.
   - Имя хранения — UUID (`storage_key`). Имя пользователя очищается от пути и управляющих
     символов и обрезается до 255 символов.
5. **Итог проверки.**
   - `clean` — документ выдаётся.
   - `infected` — файл удаляется сразу. Пишется `security.file_infected` (`actor=system`,
     сигнатура, `alert=True`): уходит оповещение ИБ, в SIEM событие попадает вместе с журналом.
   - `error` — с файлом и аудитом поступаем так же, как с `infected`. Так требует SEC-WEB-10:
     «заражённый или непроверенный файл не выдаётся и удаляется».
   - Если `clamd` недоступен, задача повторяется 5 раз с растущей паузой (1–5 мин), после
     последней попытки ставится `error`.
   - Строки «заражён» и «ошибка» видны в списке 24 часа (11.7 №3), потом их удаляет ночная
     задача.
6. **`document.scanned`** уходит в `project:{id}` после commit. Если документ за время проверки
   уже убрали в корзину, событие не шлётся. Фильтр WS не знает о корзине, а удалённые документы
   видят только модератор и пресейл (GAP-06); им итог покажет корзина.
7. **Скачивание.**
   - Отдаётся только `clean`. `pending`, `infected` и `error` → 409 `DOCUMENT_NOT_AVAILABLE` с
     `scan_status`; документ в корзине → 404.
   - Файл расшифровывается целиком до ответа: подменённый файл не уйдёт даже частично.
   - Заголовки: `application/octet-stream`, `Content-Disposition: attachment`
     (`filename="document.pdf"` и `filename*` с настоящим именем), `nosniff`, `no-store`.
   - Каждое скачивание пишется в аудит (`op=downloaded`).
8. **Корзина (GAP-06).**
   - `DELETE` переносит документ в корзину на 30 дней. Повторный `DELETE` → 204.
   - Отклонённый антивирусом документ удаляется сразу, без корзины: файла уже нет.
   - Документы в корзине появляются в `GET /projects/{id}/trash` как `kind=document`, при этом
     `batch_id` = id документа и `nodes_count=0`.
   - Корзину с документами видят модератор проекта и пресейл (пресейл — только документы,
     `documents_only`); эксперт её не видит.
   - Восстановление — только через `POST /documents/{id}/restore`. `/trash/{id}/restore` для
     документа → 404. Восстановление живого документа → 200 без изменений.
   - Ночная задача через 30 дней удаляет файл и строку и пишет аудит `op=purged`
     (`actor=system`).
9. **Статус проекта:** загрузка, удаление и восстановление в «Завершён» и «Архив» → 409 (общий
   гейт D-01). Список и скачивание работают в любом статусе.
10. **Попутно** в выгрузках (EXP-003): задачи Celery выгрузок и документов теперь идут через
    `db.session.transaction`. Поэтому хуки after-commit выполняются и в worker: события WS о
    вопросах, ставших «отправлен», и оповещения ИБ.

## Проверка

`tests/integration/core/test_documents_api.py`. Сканер в тестах подменён: он находит EICAR.
Проверяются:

- загрузка, шифртекст на диске, «Проверяется», чистый документ и скачивание с заголовками;
- `.exe` под видом `.pdf`, `.docm`/`.xlsm` (macroEnabled), `vbaProject.bin`, лимиты 50 МБ и 1 ГБ;
- EICAR → «заражён», аудит и событие; `clamd` недоступен → повтор, затем `error`; строки
  исчезают через 24 часа;
- корзина и восстановление по ролям, лимит при восстановлении, D-01, очистка через 30 дней.
