# DEC-20261109-core-totals-money-home

- **Тип:** решение (DEC), уровень A1
- **Время:** 2026-11-09T20:30:00Z
- **Трек:** CORE (CORE-026, CORE-030, CORE-033); потребители — FE-010 («Мои оценки»), FE-012
  (блок «Деньги»), RT (`money.updated`), трек портфеля (кэш итогов), QA-014
- **Основание:** SPEC ARCH-03, FR-HOME-01/02/04, 11.3, 11.6 №7–9, №13–14, BR-MONEY-01…05,
  BR-PRJ-08, Q-43, Q-44, SEC-AUTHZ-04/05, SEC-AUD-01; contracts/openapi.yaml (`listProjects`,
  `getMoney`, `putMoney`), ws-events (`money.updated`), audit-events (`project.money.changed`)

## Решение

1. **Кэш итогов (CORE-026).** Пересчёт ставит любой подъём версии проекта (`bump_version`: дерево,
   настройки, фазы, статусы веток, команда), правка денег, создание и копирование проекта. После
   commit хук ставит задачу `estimator.projects.totals` с задержкой 5 с; ключ Redis `SET NX` на 10 с
   склеивает серию правок (дебаунс), задача снимает ключ до расчёта. Модели денег доступны только
   сервису денег (G-11), поэтому расчёт и запись строки лежат в `services/money/totals.py`, а
   постановка и задача — в `services/projects/totals.py`. Не помещается в столбец — `NULL`, задача не
   падает. `project_totals_daily` (динамика портфеля, GAP-01) — задача трека портфеля.
2. **Деньги (CORE-030).** Право и TOTP проверяет gate. Для RUB курс всегда 1 (присланный курс
   игнорируется); смена валюты без курса — 422. Курс > 0 и ≤ 99 999 999,9999, не больше 4 знаков.
   Ставка `null` убирает ставку. Ставки отдаются по каждой дисциплине проекта и УП, незаданные —
   `null`. `figures` пустой, пока не заданы нужные ставки (BR-MONEY-02). `k` — 6 знаков.
3. **Аудит и история.** `project.money.changed` — только названия полей и id дисциплин
   (SEC-AUD-01). Значения «было → стало» — в журнале проекта (`is_money`): это история ставок для
   модераторов, её покажет CORE-032. Правка без изменений ничего не пишет.
4. **`money.updated`** уходит в `project:{id}:money` при правке денег, без новой версии проекта
   (дерево не меняется, change_log денег не хранит). `totals` — «в КП» по «Цифре для КП» и
   стоимость по E. Пересчёт денег при правке дерева клиент делает сам (ARCH-03).
5. **«Мои оценки» (CORE-033).**
   - Деньги в строке — только где пользователь модератор или пресейл проекта и TOTP пройден.
     Руководитель пресейла видит деньги в реестре портфеля, не здесь (FR-HOME-04).
   - Прогресс у эксперта — ветки включённых фаз по его дисциплинам. У модератора и пресейла — все
     ветки проекта (у пресейла SPEC прогресса не задаёт, берём проект целиком). «Подготовка» без
     экспертов — `my_progress = null` («команда не назначена»).
   - Дедлайн красный: ≤ 2 рабочих дня (или уже прошёл) и мои ветки не все «готово»/«не нужно».
   - «Мне» — непрочитанные уведомления `question_to_me`, `answer_to_my_question`,
     `question_redirected`, `moderator_change` этого проекта.
   - «Дата изменения» — позднее из `projects.updated_at` и последнего события `change_log`.
   - `quote_hours` — из кэша; нет строки кэша или E = 0 — `null` («—»).
   - Поиск — от 2 символов по названию и заказчику; короче — без поиска.
   - Курсор — ключ сортировки последней строки (с «Мне» > 0, дедлайн, название, id).
