# Отчёт DB-013 и EXP-013: запросы и выгрузка

Замеры от 11.11.2026, сделаны на локальной машине агента: PostgreSQL 16, данные в одной
транзакции теста, после `ANALYZE`. Окончательные замеры делаются на стенде stage (QA-020).

## DB-013: планы ключевых запросов

Тест `test_query_plans.py` берёт проект «со всем» (ставки, вопросы, вопрос заказчику, заметки,
снимок, документ, корзина) и добивает его до 5 000 живых узлов, это предел BR-TREE-06. Потом он
открывает 13 экранов через API и записывает каждый SELECT приложения: 138 запросов. Для каждого
строится план с `enable_seqscan = off`. В таком режиме планировщик берёт индекс всегда, когда тот
подходит, поэтому «Seq Scan» в плане означает одно: подходящего индекса нет. От объёма данных
проверка не зависит. Последовательный скан большой таблицы (узлы, история, журнал изменений,
обсуждения, уведомления, аудит, участники и другие, список `LARGE` в тесте) роняет тест.

Повторить с отчётом EXPLAIN ANALYZE по каждому запросу:

```sh
PERF_REPORT=/tmp/plans.md uv run pytest tests/perf/test_query_plans.py
```

### Что нашлось

| Экран | Запрос | Было | Исправление |
|---|---|---|---|
| Обсуждения проекта | все треды проекта, новые сверху | Seq Scan `threads`: частичный индекс `threads_project_open_idx` подходит только открытым тредам | индекс `threads_project_created_idx (project_id, created_at DESC, id DESC)`, миграция `0010_query_indexes` (expand) |

Остальные 137 запросов идут по индексам из SPEC 14.3 и `contracts/db/schema.md`. Попутно
`DISTINCT ON` в ленте сообщений переведён на `postgresql.distinct_on`: прежняя форма
устарела в SQLAlchemy 2.1.
