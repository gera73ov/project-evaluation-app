# Моки API (FE-001)

Фронтенд работает без бэкенда: `cd frontend && npm run dev:mock` → http://localhost:5173.
Service Worker [MSW](https://mswjs.io) перехватывает `/api/v1/*` и WebSocket `/api/v1/ws`.
В сборку для стендов моки не попадают (`npm run build` проверяет это в `scripts/check-build.mjs`).

## Откуда ответы

| Файл | Что делает |
|---|---|
| `contract.ts` | читает `contracts/openapi.yaml`, `permissions.yaml`, `ws-events.schema.json` |
| `personas.ts` | роли переключателя и права по `permissions.yaml` (раздел `grants`) |
| `data.ts` | «Портал дилеров» (из `contracts/fixtures/calc/portal-dilerov.json`) и «Интеграция с ФНС» |
| `responses.ts` | права → 404 / 403 / ответ; демо-ответы главных экранов |
| `sample.ts` | пример по схеме для остальных операций; удаление денежных ключей |
| `ws.ts` | имитатор WebSocket: `ack` на команды, события по сценарию раз в 20 с |
| `handlers.ts` | обработчики MSW для браузера и тестов |
| `mocks.test.ts` | каждая операция × каждая роль проходит схему OpenAPI, события — схему WS |

Демо-ответы есть у `getMe`, `listProjects`, `getProject`, `getMembers`, `getTree`, `getMoney`,
`getStats`, `listNotifications`, `listPhases`, `listDisciplines`, `listNodeTypes`. Остальные
операции отвечают примером по схеме контракта. Изменяющие запросы ничего не сохраняют.

это проверяет сервер.

## Когда меняется контракт

Моки читают контракты напрямую, поэтому новая операция OpenAPI сразу получает обработчик.
`npm test` упадёт, если демо-ответ разошёлся со схемой: тогда правится `responses.ts` или
`data.ts` в том же PR, что и контракт (PLAN.md 1.3 п. 6).
