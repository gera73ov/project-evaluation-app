# E2E (FE-090, FE-091, FE-092, FE-094, FE-081, FE-093, FE-080, QA-018)

Playwright-сценарии UI против настоящего API.

## Запуск на dev-стенде

```bash
cd e2e && npm ci
E2E_BASE_URL=https://dev.example.local \
E2E_SEED_CMD='docker compose -f ../deploy/compose/docker-compose.yml exec -T api python /e2e/auth/seed.py' \
E2E_WORK_SEED_CMD='docker compose -f ../deploy/compose/docker-compose.yml exec -T api python /e2e/work/seed.py' \
E2E_ADMIN_SEED_CMD='docker compose -f ../deploy/compose/docker-compose.yml exec -T api python /e2e/admin/seed.py' \
E2E_STATS_SEED_CMD='docker compose -f ../deploy/compose/docker-compose.yml exec -T api python /e2e/stats/seed.py' \
E2E_STATS_FILL_CMD='docker compose -f ../deploy/compose/docker-compose.yml exec -T api python /e2e/perf/fill.py' \
E2E_A11Y_SEED_CMD='docker compose -f ../deploy/compose/docker-compose.yml exec -T api python /e2e/a11y/seed.py' \
E2E_A11Y_FILL_CMD='docker compose -f ../deploy/compose/docker-compose.yml exec -T api python /e2e/perf/fill.py' \
E2E_DISCUSSIONS_SEED_CMD='docker compose -f ../deploy/compose/docker-compose.yml exec -T api python /e2e/discussions/seed.py' \
E2E_DISCUSSIONS_FILL_CMD='docker compose -f ../deploy/compose/docker-compose.yml exec -T api python /e2e/perf/fill.py' \
npx playwright test
```

## Запуск без Docker

Нужны Postgres и Redis, применённые миграции (`uv run estimator migrate`) и API на `127.0.0.1:8000`
с `APP_BASE_URL=https://localhost:8443`, а также worker Celery (`uv run celery -A
estimator.jobs.celery_app worker`): он пересчитывает итоги проекта для портфеля после правок, строит
выгрузки и отдаёт документы на проверку антивирусу. Вместо контейнера ClamAV подойдёт заглушка
`python3 e2e/tools/fake_clamd.py` (порт 3310) и `CLAMAV_HOST=127.0.0.1` у API и worker; у обоих
нужны также `EXPORTS_DIR` и `DOCUMENTS_DIR` с правом записи. Затем:

```bash
(cd frontend && npm run build)
cd e2e && npm ci && npx playwright test
```

Без `E2E_BASE_URL` поднимается `serve.mjs` — замена Nginx стенда: HTTPS на 8443, статика
`frontend/dist`, nonce в CSP, прокси `/api`. Самоподписанный сертификат создаётся в `e2e/.tls`.
`global-setup.ts` запускает `auth/seed.py`: тот создаёт пользователя и администратора со случайными
логинами, поэтому повторный прогон не мешает прошлому. Лимит входа с одного IP (20 в минуту) при
частых локальных прогонах сбрасывается очисткой Redis. Внутри прогона сценарии сами держатся в
лимите: перед входом `auth/budget.ts` ждёт, пока за минуту не освободится место.

## Сценарии

- `auth/` — вход, TOTP, резервные коды, профиль (FE-090).
- `work/` — рабочий экран (FE-091): модератор создаёт проект, добавляет дисциплину и двух экспертов,
  запускает оценку; эксперты в отдельных браузерах видят новые узлы и правки друг друга, захват ячейки,
  полосу «Нет связи» и догрузку после восстановления; перехват ячейки модератором даёт эксперту диалог
  конфликта; исключённый из команды видит «Доступ к проекту закрыт». Данные создаёт `work/seed.py`
  (модератор с TOTP и два эксперта со случайными логинами). Разрыв связи имитируется через
  `page.routeWebSocket`: `context.setOffline` уже открытый WebSocket не закрывает.

- `admin/` — админка администратора (FE-094): пользователи (создание, роли, сброс пароля с
  подтверждением кодом), справочники и «Пороги и проценты», производственный календарь (правка дня
  сохраняется и возвращается обратно), предложенный тип из проекта, реестр проектов (блокировка
  последнего модератора → «без модератора», назначение нового, режим поддержки). Данные создаёт
  `admin/seed.py`: администратор, два модератора и пользователь. Системная часть (суперадминистратор,
  AD, журнал аудита) появится вместе с её серверной частью.

- `stats/` — статистика, снимки и портфель (FE-093): итоги вкладки «Итоги» совпадают с сервером и
  верхней панелью рабочего экрана, «Напомнить не начавшим» уходит эксперту ветки, снимок
  «v1 — КП отправлено» → правка оценки → сравнение с текущим, руководитель пресейла находит проект в
  портфеле и становится модератором. Данные создаёт `stats/seed.py` (модератор, руководитель пресейла,
  эксперт), узлы — `perf/fill.py` на 60 узлов. Выгрузки проверяет `discussions/`.

- `discussions/` — «типовой день эксперта» SPEC 4.5 (FE-092) и выгрузки (FE-093): эксперт под листом
  спрашивает @заказчик с «нужен ответ» и пишет в комментарии «Допущение: …»; пресейл выгружает
  вопросы в Word и вносит ответ заказчика; эксперт по уведомлению переходит к строке, сужает вилку и
  отмечает ветку «Готово». Модератор пишет закрытую заметку (у эксперта вкладки нет), выгружает Excel
  «С деньгами» (в файле гриф «Коммерческая тайна» и ФИО) и загружает документ заказчика, который
  после проверки антивирусом скачивается. Затем модератор ставит результат пресейла «выигран» с суммой договора и
  меняет на «проигран» с причиной; журнал проекта показывает эти записи и дисциплины, команду, статус
  русскими подписями полей. Данные создаёт `discussions/seed.py` (модератор, эксперт,
  пресейл), узлы — `perf/fill.py`. Содержимое docx и xlsx сценарий читает из XML внутри файла.

- `a11y/` — аудит доступности axe (FE-080): WCAG 2.1 A/AA, нарушения serious и critical валят
  сценарий. 25 экранов, которые уже работают на сервере (вход, «Мои оценки», рабочий экран, настройки,
  документы заказчика, вкладки статистики, снимки и сравнение, профиль, портфель, админка), панель
  обсуждения с закрытыми заметками, меню «Экспорт ▾» и ввод оценки с клавиатуры. Ещё два сценария
  рабочего экрана: на 1366 px дерево без горизонтальной прокрутки, на 1024 px дерево прокручивается
  со столбцом «Узел» на месте, у кнопок полосы остаются иконки, P90 уходит в подсказку у P80 (DESIGN
  9.10); обход Tab от начала страницы до ячейки O листа (у каждого шага видимый фокус и имя), меню
  «Экспорт ▾» и диалог снимка с клавиатуры (Esc возвращает фокус), «Начать обсуждение» без мыши.
  Данные создаёт `a11y/seed.py` (модератор, он же руководитель пресейла, и администратор), узлы —
  `perf/fill.py`. Отчёт axe по каждому экрану — вложение `axe.json`.

- `perf/` — замеры рабочего экрана на 5 000 узлах (FE-081): открытие, ввод O, прокрутка. В общий
  прогон не входят: `E2E_PERF=1 npx playwright test perf` (на стенде ещё `E2E_PERF_SEED_CMD` и
  `E2E_PERF_FILL_CMD` — команды `perf/seed.py` и `perf/fill.py` в контейнере api; к второй сценарий
  дописывает id проекта и число узлов). `E2E_PERF_PROFILE=1` прикладывает профиль CPU на время ввода.
  Результаты и разбор — `perf/REPORT.md`.

`serve.mjs` проксирует и WebSocket `/api/v1/ws`. Все сценарии проверяют, что в консоли нет нарушений CSP.
Chromium запускается с `LANG=C.UTF-8` (`playwright.config.ts`): без UTF-8-локали он заменяет
кириллическое имя скачанного файла на `download`.
