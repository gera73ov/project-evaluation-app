# CR-019 · Колонка «Комментарий» рабочего экрана

| Параметр | Значение |
|---|---|
| Статус | Принято владельцем продукта 28.11.2026, внесено в SPEC v0.7 |
| Дата | 28.11.2026 |
| Инициатор | Владелец продукта |
| Затрагивает | SPEC 2 (глоссарий, «Метка комментария»), FR-TREE-02, 7.5 (справочник меток), 11.4 №19, 11.10 №4, 19 (D-33); DESIGN.md 2.4, 6.4, 6.5, 9.x «Норма типа»; фронтенд рабочего экрана. API и БД не меняются |

## Суть

Владелец продукта разобрал колонку «Комментарий» на стенде и сделал три замечания:

1. В строке пустого листа стоит фраза «Норма: на раздел 2–4–6 · подставить». Непонятно, откуда она и зачем. По SPEC подсказка нормы должна была стоять под полями O/R/P, а интерфейс показывал её в колонке комментария вместо заглушки «Нажмите, чтобы добавить комментарий».
2. Метки в комментарии сокращены («Огр.», «Тех.»). Их надо писать полностью.
3. Метка сливается с текстом комментария. Все метки были одного бледно-голубого цвета, хотя DESIGN.md 2.4 задаёт свой цвет каждой метке.

## Решения владельца продукта (27.11.2026)

| № | Решение | Почему |
|---|---|---|
| 1 | Подсказку нормы типа на рабочем экране убрать совсем. Нормы остаются в справочнике типов; O/R/P по-прежнему не подставляются | Подсказка путалась с комментарием и отвлекала |
| 2 | Метки комментария везде показывать полным названием из справочника: в ячейке, в раскрытии, в плашке «+N», в редакторе. Короткое имя метки на рабочем экране не используется | Полное название читается без расшифровки, ширины колонки (от 240 px) хватает |
| 3 | Метку отделить от текста цветом по категории (DESIGN 2.4), плашкой с рамкой и отступом 8 px до текста | DESIGN это уже требовал; цвет сразу говорит о смысле метки |

Решение 3 только приводит интерфейс к DESIGN.md и SPEC не меняет; оно записано здесь, чтобы изменения колонки были в одном месте.

## Что не меняется

- API, схема БД и контракты: нормы по-прежнему хранятся у типа (`node_types.norms`) и редактируются в админке; поле `short_name` у меток остаётся.
- Выгрузки Excel и Word уже пишут полное название метки.
- Макеты в `docs/spec/img/` с «Огр.» и «Тех.» не перерисовываются: текст SPEC важнее картинки.
