## Что нашлось: CR-017

У 28 операций есть параметры запроса, которые сервер проверяет: обязательные (`q`, `from`/`to`,
`since`, `with`, `format`), перечисления (`status`, `role`, `result`), даты, `uuid`, флаги. При
неверном значении сервер отвечает 422 `VALIDATION_FAILED`, а в контракте этого ответа не было.
Пример: `GET /portfolio/summary` без `from` и `to`. Нашёл замер DB-013.

Исправление CR-017: этим 28 операциям добавлен ответ `422` (`Problem422`) и код
`VALIDATION_FAILED` в `x-error-codes`. Поведение сервера не меняется, TS-типы перегенерированы.
Новый тест держит правило дальше: если сервер проверяет параметр запроса, контракт объявляет
422. Курсор и размер страницы сюда не входят, на них сервер отвечает 400 `CURSOR_INVALID`.
Неверный id в пути даёт 404.
