# Контракты между треками

Каталог хранит договорённости, на которые опираются несколько треков одновременно
(PLAN.md раздел 6). Контракты фиксируются на этапе 0 и утверждаются задачей PM-001 (веха M0). Версия 1.0 утверждена 05.11.2026,
тег репозитория `contracts-v1.0`; с этого момента действует порядок CR ниже.

## Порядок изменений (CR)

До вехи M0 контракт меняет его трек-владелец обычным PR с ревью треков-потребителей.

После M0 любое изменение идёт через запрос на изменение (PLAN.md раздел 14, правило 6 раздела 1.3):

1. Инициатор добавляет строку `CR-NNN` в раздел 14 PLAN.md: дата, инициатор (трек), контракт,
   суть, затронутые задачи, ревьюеры, статус `предложено`.
2. Трек-владелец контракта готовит PR, который меняет файл контракта; ID `CR-NNN` указывается
   в заголовке или описании PR и в `Refs:` коммита.
3. Ревью обязательны от всех треков-потребителей из таблицы раздела 6 PLAN.md.
4. Ломающее изменение помечается `!` и `BREAKING CHANGE:` (AGENTS.md 5.3.2), а моки фронтенда
   FE-001 обновляются в том же PR.
5. После слияния статус CR меняется на `действует`.

Контракт не может противоречить SPEC. Если противоречие найдено, заводится GAP в разделе 11.2
PLAN.md, решение принимает владелец продукта (правило 7 раздела 1.3).
